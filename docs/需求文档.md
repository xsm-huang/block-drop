# Block Drop 移动端单机小游戏需求文档

版本：v1.0 · 日期：2026-10-12 · 状态：首版产品需求已确认

## 1. 产品定位

面向个人自用的 Android 竖屏俄罗斯方块小游戏。核心体验为轻松休闲、单手操作、现代简洁。完全离线，无账号、广告、内购，不申请无关权限。

首版仅包含一个经典无限模式：方块缓慢自动下落，保持固定速度，不随得分或消行数加速。对局持续至棋盘无法生成新方块。

## 2. 已确认的范围

| 项目 | 首版要求 |
| --- | --- |
| 平台 | Android，竖屏，优先手机 |
| 操作 | 点击旋转、左右滑动移动、普通下滑移动、快速下滑落底 |
| 辅助 | 当前方块落点提示 |
| 记录 | 本地最高分、未完成对局保存与恢复 |
| 反馈 | 音效、轻微震动，分别支持开关 |
| 视觉 | 微圆角色块、细间隙、深灰背景、柔和且容易区分的配色 |
| 暂停 | 手动暂停，切到后台自动暂停 |

首版不包含下一个方块预览、暂存方块、关卡、多模式、在线排行、联机、账号同步、主题商店。iOS 与 Web 不作为首版验收平台。

## 3. 核心玩法

### 3.1 棋盘与方块

- 采用经典 10 列 × 20 行可见棋盘。
- 保留 I、O、T、S、Z、J、L 七种四格方块，每种形状使用固定颜色。
- 方块不得越过棋盘左右边界、底部或穿过已锁定方块。
- 点击一次顺时针旋转 90°；O 方块旋转后外观与占格不变。
- 靠墙旋转时尝试合理的位置调整；无法找到有效位置则保留原位置与方向。
- 当前方块下方显示最终落点轮廓，移动、旋转后即时更新。
- 横排填满后消除，同一次锁定形成的满行一起消除，上方方块向下补齐。
- 新方块无法在出生位置生成时结束游戏。

棋盘尺寸是经典玩法的实施默认值；随机生成算法、出生位置与旋转补偿表见第 10 节，属于技术实现细化项。

### 3.2 下落与锁定

- 方块以固定的慢速自动下落，无等级加速。
- 普通手动下滑按手指移动距离逐格下移，松手后恢复自动下落。
- 普通下落触底后，保留约 0.5 秒调整时间，可移动或旋转。
- 触底调整不得无限延长锁定时间，具体重置上限在实现时确定。
- 快速下滑使方块立即移动到落点并锁定，无额外调整等待。
- 锁定后完成计分、消行与下一块生成；玩家不能继续操控已锁定方块。

### 3.3 计分

| 得分来源 | 规则 |
| --- | --- |
| 基础分 | 每个方块成功锁定 +10 分，自然下落同样获得 |
| 普通手动下滑 | 实际向下移动每格额外 +1 分 |
| 快速下滑 | 从当前位置到落点实际移动每格额外 +2 分 |
| 一次消除 1 行 | +100 分 |
| 一次消除 2 行 | +300 分 |
| 一次消除 3 行 | +500 分 |
| 一次消除 4 行 | +800 分 |

- 总分为基础分、操作加分和消行分之和。
- 自动下落、左右移动、旋转、落点提示不产生操作加分。
- 被障碍阻止的移动不计分；同一段下移距离不得同时算作普通下滑与快速下滑。
- 快速下滑距离为 0 格时，操作加分为 0，但成功锁定仍获得基础分。
- 首版不含连击、特殊旋转、连续四行等奖励规则。

示例：自然下落并锁定且未消行得 10 分；普通下滑 3 格，再快速下滑 5 格，锁定并消除 1 行，共得 10 + 3 + 10 + 100 = 123 分。

## 4. 单手手势交互

游戏主要操作集中在棋盘触摸区域，不依赖双手或屏幕方向按钮。暂停入口应方便单手触达，按钮与棋盘的触摸区域相互独立。

| 手势 | 行为 |
| --- | --- |
| 点击 | 当前方块顺时针旋转一次 |
| 左右滑动 | 按滑动距离逐格移动，可一次连续移动多格；抬手后停止横移 |
| 普通速度下滑 | 按距离逐格下移，松手后恢复自动下落 |
| 快速下滑 | 直接落底并锁定 |

手势识别要求：

- 一次触摸只识别一种操作，滑动结束后不再触发点击旋转。
- 以主要滑动方向区分横移与下移，避免斜滑同时触发两类操作。
- 点击容许少量手指抖动，具体距离阈值需在 Android 真机调试。
- 普通下滑和快速下滑应易于区分；阈值不以未经验证的固定数值作为产品承诺。
- 同一次向下触摸一旦判定为快速下滑，仅执行一次落底，不影响随后生成的新方块。
- 若识别快速下滑前已经实际执行普通下移，已移动部分按普通下滑计分，剩余落底距离按快速下滑计分。
- 方块锁定后，原触摸序列不继续操控新方块，需重新触摸。
- 暂停、结算、切后台及触摸被系统取消时，停止接受该次游戏手势。
- 首版不为上滑和多指触摸分配游戏动作。

## 5. 页面与流程

### 5.1 首页

- 展示游戏名称与历史最高分。
- 无存档时显示“开始游戏”；有有效存档时显示“继续游戏”和“新游戏”。
- 点击“新游戏”直接覆盖未完成进度并进入新对局，不再二次确认；最高分保留。首次游玩仍展示一次操作教学。
- 点击“继续游戏”直接进入并恢复对局，不再在游戏页点击一次继续；应用切后台后回到前台仍保持暂停。
- 提供设置入口，包含音效和震动两个独立开关。

### 5.2 游戏页

- 展示当前得分、最高分、棋盘、当前方块与落点提示。
- 提供易于单手触达的暂停按钮。
- 不显示下一个方块预览或暂存区域。
- 首次游戏提供简短操作提示，不持续遮挡棋盘；提示点击旋转、左右移动、下滑移动、快速下滑落底。

### 5.3 暂停弹层

- 冻结下落与游戏输入，提供“继续”和“返回首页”。
- 返回首页前保存当前对局。
- Android 系统返回操作在游戏进行中先进入暂停状态。
- 切后台自动暂停；回到前台后由用户主动点击继续，不立即下落。

### 5.4 结算弹层

- 显示本局得分、历史最高分，刷新纪录时给予清晰提示。
- 提供“再来一局”和“返回首页”。
- 已结束对局不再作为可继续的存档。

主要流程：进入首页 → 开始或继续 → 游戏 → 暂停后继续／返回首页，或游戏结束 → 结算 → 再来一局／返回首页。

## 6. 本地记录与续玩

- 本地持久化最高分、音效设置、震动设置和未完成对局。
- 存档至少包含棋盘、当前方块类型／位置／方向、得分，以及恢复生成序列所需的随机状态。
- 方块锁定、暂停、返回首页和进入后台时保存；对局中需合并保存最新操作状态，避免高频写入影响手感。
- 正常退出后继续时，应恢复到最近保存的完整有效状态，并保持暂停等待用户继续。
- 普通后台停留不补算离线下落或离线得分。
- 最高分在本局超过历史纪录时更新，不依赖玩家主动结束对局。
- 存档缺失、损坏或版本不兼容时，给出简短提示并允许开始新游戏，不导致闪退；尽量保留独立保存的最高分和设置。
- 系统强制终止时可能只能恢复最近成功写入的状态，具体丢失窗口需在实现与真机测试中验证。
- 卸载或清除应用数据后，本地记录不保证保留，首版不提供云备份。

## 7. 视觉与反馈

- 采用现代简洁风格，深灰背景，棋盘网格弱化。
- 方块使用微圆角、细间隙，避免圆角过大影响四格形状辨识。
- 七种方块固定配色，颜色柔和但需要与背景保持足够对比度。
- 落点提示使用对应颜色的细轮廓，与实体方块明显区分。
- 消行和落底可使用短促、克制的动画，不添加持续发光或复杂特效。
- 反馈覆盖旋转、落底、消行和游戏结束等关键动作，避免高频移动产生密集音效或震动。
- 音效与震动开关立即生效并持久化；关闭后对应反馈完全停止。
- 适配 Android 安全区域与不同手机比例，棋盘格子保持正方形，核心控件不被系统区域遮挡。

## 8. 非功能要求与项目约束

- 首次启动及完整对局均可在无网络环境下完成。
- 手势反馈应流畅，无明显输入延迟；以常见 Android 真机稳定接近 60 fps 为性能目标，待实现后实测。
- 长时间运行、反复暂停续玩和快速连续操作不应出现穿模、重复锁定、重复计分或多个下落计时器并行。
- 游戏规则、渲染、手势和存档职责分离，便于独立验证规则。
- 项目当前为 Expo 57、React Native、TypeScript 初始模板，已有竖屏配置，尚无游戏逻辑。
- 后续页面导航按项目约定采用 Expo Router；业务组件、规则和工具不放入路由目录。
- 实现任何 Expo／React Native API 前，必须查阅对应 SDK 版本文档；依赖通过 Expo 安装命令选择兼容版本。
- 本阶段仅梳理需求，不新增依赖、不修改应用代码。

## 10. 实现前与真机调试时细化的参数

以下不改变已确认的产品范围，先列为实施建议或待验证参数，不视为用户已确认的精确数值：

| 项目 | 建议／待定内容 |
| --- | --- |
| 自动下落间隔 | 以每格约 1 秒作为初始调试值，按休闲体验调整 |
| 随机算法 | 建议采用七袋随机，减少某种方块长时间不出现 |
| 出生与旋转 | 确定出生方向、隐藏行处理和固定旋转补偿表，保证行为一致 |
| 触底调整上限 | 明确有效移动／旋转能否重置计时，以及次数上限 |
| 手势阈值 | 点击容差、滑动距离换算、方向锁定、快速下滑速度与最小位移 |
| 反馈默认值 | 建议音效、轻微震动默认开启，允许分别关闭 |
| 存档策略 | 合并写入间隔、异常终止的恢复窗口、存档版本迁移方式 |
| 视觉细节 | 七色调色板、圆角半径、间隙尺寸、动画时长 |

## 11. 建议开发顺序

1. 实现棋盘、方块、碰撞、旋转、锁定、消行和计分规则。
2. 实现竖屏游戏界面、单手手势与落点提示，优先真机验证操作手感。
3. 完成首页、暂停、结算、最高分、存档恢复与后台行为。
4. 加入音效和震动开关，打磨视觉与反馈，按验收表进行真机检查。

后续扩展另行确认，不自动纳入首版。
