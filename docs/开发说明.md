# 开发与运行说明

首版为 Android 竖屏应用。需求见 [需求文档](./需求文档.md)，实现进度与验证限制见 [开发记录](./开发记录.md)。

## 本地环境

- 当前统一使用 pnpm 12.4.2 与 pnpm-lock.yaml，package.json 已声明 packageManager。保留此前的 package-lock.json 作为历史文件，EAS 上传排除它，避免锁文件选择歧义；不要交替使用 npm install 和 pnpm install。
- 当前实现使用 Expo 57.0.28。推荐 Node.js 24 LTS；规则测试使用 Node 内置测试器，存储测试使用 Node 内置 SQLite。
- Windows PowerShell 使用 `pnpm.cmd` 和 `npx.cmd`，避免系统执行策略阻止 .ps1 包装脚本。Git Bash 可直接使用 pnpm。

在项目根目录运行：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd test
pnpm.cmd run typecheck
pnpm.cmd run lint
```

## 安卓体验与验证

启动本地开发服务器：

```bash
pnpm start
```

如果安装阶段出现 `ERR_PNPM_IGNORED_BUILDS`，检查具体包名。当前已审核并在 pnpm-workspace.yaml 中单独允许 unrs-resolver 的构建脚本（ESLint 依赖的原生解析器）。在其他环境仍提示该包时，可运行：

```bash
pnpm approve-builds unrs-resolver
pnpm rebuild unrs-resolver
pnpm start
```

审批对应 `allowBuilds.unrs-resolver: true`，不要用全局允许所有脚本的方式代替。详见 [pnpm 构建审批文档](https://pnpm.io/cli/approve-builds)。日志中的下载速度与 ESLint 弃用提示不是此次启动中断的直接原因。

项目已接入带原生能力的 SQLite、音效和震动。新增原生模块后按项目规则使用原生构建验证，不将 Expo Go 的结果作为完整验收。

已提供 EAS `preview` 配置，可构建直接安装的 APK；本轮尚未登录 EAS、关联云端项目或提交云构建，也未生成 APK。首次使用需要 Expo 账号，并按 CLI 提示确认项目关联和 Android 签名配置。

```powershell
npx.cmd eas-cli@latest login
npx.cmd eas-cli@latest build --platform android --profile preview
```

构建完成后从 EAS 提供的链接下载安装。预览 APK 包含 JS 和音效，安装后不依赖本地开发服务器，可断网验证对局与存档。构建选项依据 [EAS 配置文档](https://docs.expo.dev/build/eas-json/)。

当前没有安装 expo-dev-client，也没有声明 developmentClient 构建配置。若后续需要真机热更新调试，再安装开发客户端并创建开发构建；单纯启动 Metro 不能替代 APK 或开发客户端。

## 本地资源打包检查

```powershell
npx.cmd --no-install expo export --platform android --output-dir dist
```

该命令检查路由、JS 和资源能否导出 Android 包内容；输出不是可安装 APK，不能证明原生运行、手势手感或帧率已通过验收。dist 已被 Git 忽略。

## 代码入口

| 路径 | 职责 |
| --- | --- |
| src/app | Expo Router 入口与两个页面路由 |
| src/screens | 首页和游戏页装配 |
| src/game/engine.ts | 纯游戏规则与计时 |
| src/game/input.ts / board-input.ts | 手势算法与原生输入适配 |
| src/game/store.ts | 唯一对局状态、时钟、保存和反馈调度 |
| src/services | SQLite、存档校验、保存队列与反馈 |
| src/components / theme.ts | 棋盘、弹层、按钮与视觉参数 |
| tests | 引擎、手势、SQLite 事务与控制器测试 |
