# 技术架构与存档设计

基线：[需求文档](../需求文档.md) · [引擎契约](./游戏引擎设计.md) · [交互契约](./界面与交互设计.md)

## 1. 当前项目与技术选择

当前 package.json 为 Expo `~57.0.27`、React `19.2.3`、React Native `0.86.3`、TypeScript `~6.0.3`；入口仍为 index.ts → App.tsx，尚未接入路由与游戏模块。本次仅输出设计，不安装依赖或迁移入口。

| 能力 | 实施方案 | 原因 |
| --- | --- | --- |
| 导航 | Expo Router，两条页面路由 | 遵循项目约定，弹层留在页面内 |
| 规则 | 纯 TypeScript 模块 | 可确定性测试，不依赖设备 |
| 游戏状态 | 局内控制器持有单一状态，对 UI 发布快照 | 避免计时与手势读取过期闭包 |
| 渲染 | 首版原生视图格子和绝对定位活动层 | 200 个可见格，先控制重绘，再按实测决定是否更换绘制方式 |
| 手势 | 棋盘独占的输入适配器 | 平台触摸信息转换为命令，不将规则写入事件回调 |
| 持久化 | expo-sqlite，单一数据库连接和串行写队列 | 原子提交对局与最高分，避免半存档 |
| 音效 / 震动 | expo-audio / expo-haptics | 使用 Expo 模块，反馈失败不影响游戏 |
| 安全区域 | react-native-safe-area-context | 布局与系统导航区域隔离 |

本设计不预先增加全局状态库、绘图引擎或动画库。手势适配器具体选用基础触摸接口还是专用手势库，需实现前核对对应版本文档并做最小真机原型；外部库不得改变本文的命令契约。

Expo 模块能力依据已核对的 [SDK 57 文档](https://docs.expo.dev/versions/v57.0.0/)、[SQLite](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/)、[Audio](https://docs.expo.dev/versions/v57.0.0/sdk/audio/)、[Haptics](https://docs.expo.dev/versions/v57.0.0/sdk/haptics/) 与 [Router](https://docs.expo.dev/router/introduction/)。具体调用、配置与权限在实施时再查对应页面；SQLite 用于重启后持久化，Audio 仅用于本地播放，不启用录音或后台播放。

## 2. 建议目录

```text
src/
  app/
    _layout.tsx             # 根导航与服务装配
    index.tsx               # 首页路由
    game.tsx                # 游戏路由
  components/
    board/                  # Board、Cell、ActivePiece、GhostPiece
    dialogs/                # 暂停、结算、设置、覆盖确认
    ui/                     # Button、ScoreLabel、Toggle
  game/
    engine/                 # 类型、形状、碰撞、旋转、随机、计分、状态转移
    controller/             # 单一状态所有者、命令调度、前台时钟
    input/                  # 手势识别、方向锁定、距离累积
    presentation/           # 显示快照选择与动画描述
  services/
    persistence/            # 数据库、校验、迁移、串行保存队列
    feedback/               # 音效和震动适配
  theme/                    # 色板、间距、圆角、文字尺寸
  tests/                    # 引擎与存档关键用例
assets/audio/               # 随包提供的短音效
```

路由文件只做页面装配。引擎不得 import React、React Native、Expo、存储或音效模块。依赖方向为页面 → 控制器 → 引擎，控制器通过存储和反馈接口处理副作用。

## 3. 控制器与时钟

- 一个对局只有一个控制器；页面重渲染不创建第二个计时器，不重复订阅生命周期。
- 所有命令串行处理：输入／时钟 → 引擎 → 更新唯一快照 → 发布 UI → 调度保存与反馈。
- 控制器的实例外提供订阅和快照读取，避免把每帧 elapsed 作为整个页面状态。
- 时钟只在游戏页可见、应用前台、phase 为 running 时推进；调度方法在实现时核对 React Native 版本文档。
- 使用单调时间，进入暂停前先推进至当前时刻，再冻结剩余计时；继续时重设时间基线。
- 输入到来时，先推进到事件处理时刻，再校验手势绑定的 pieceId；若方块已锁定，则忽略旧操作。
- 单次时间差超过 250ms 的初始保护阈值时，进入暂停而非追赶大段时间，避免卡顿后连落多格。该阈值需真机验证，普通短帧延迟正常分段推进。
- 离开游戏页或销毁控制器时取消时钟、手势、订阅与待播放反馈。

反馈事件通过 `(sessionId, revision, eventIndex)` 去重，不在渲染函数中播放。存档恢复不重放过去的声音、震动或得分动画。

## 4. 持久化模型

使用一个 SQLite 数据库，三个逻辑记录表；所有动态值参数化写入。

| 记录 | 关键字段 |
| --- | --- |
| profile（单行） | bestScore、soundEnabled、hapticsEnabled、tutorialSeen |
| active_session（单行） | schemaVersion、rulesVersion、sessionId、revision、savedAt、payload |
| metadata | 数据库结构版本与迁移状态 |

`payload` 为完整 JSON 快照，包含：

```text
board: 22×10 的 null/方块类型
active: type, rotation, x, y, pieceId
score: 非负安全整数
random: algorithmVersion, state, remainingBag
timing: gravityRemainingMs, lockRemainingMs 或 null, lockResetCount
nextPieceSequence: 用于生成下一 pieceId 的递增序号
phase: ready/running/paused（载入后统一转换为 paused）
```

sessionId、revision 与版本属于外层快照字段，不依靠 savedAt 判断新旧；savedAt 只用于诊断。可见状态、随机状态和计时必须同批提交，不分别写“分数”和“棋盘”。

游戏结束后事务删除 active_session，同时更新 bestScore；不保存可继续的 gameOver 对局。再来一局与覆盖存档事务写入新 sessionId，队列中旧对局写入随后全部失效。

## 5. 保存调度与并发

1. 状态改变后标记脏，普通移动与操作得分采用最多每 500ms 一次的节流合并，并设置最大等待 500ms，持续触摸也会保存。
2. 锁定、暂停、离开首页前的对局切换、返回首页、进入后台及新游戏启动触发立即保存请求；已进入后台的写入尽力完成，不假定系统无限提供执行时间。
3. 只有一个写入队列。请求保存时捕获完整不可变快照，队列可合并未执行的同对局旧 revision，但不能打乱覆盖或结束事务。
4. 写入前检查当前会话代次；已结束／被替换对局的请求丢弃，防止旧存档复活。新会话使用新的 sessionId 与控制器代次。
5. 对局快照与 `bestScore = max(已有最高分, 快照分数)` 在同一事务提交；单独设置更新不能覆盖最高分。
6. 返回首页时冻结对局，等待保存成功再导航。失败保留暂停状态，提示重试；如提供仍然离开的选项，明确本次进度尚未保存。
7. 保存失败不清空内存，不循环无间隔重试。队列保留最新待保存状态，下次主动保存或短暂退避后重试。

目标为强制结束时通常最多丢失约 500ms 加实际写入耗时，不能作为绝对保证；系统杀进程、存储错误和后台写入中断可能扩大窗口。正常返回首页的保存必须等待完成。最高分与对局同批更新，正常操作可保留最新记录，极端中断仍只能保证最近成功提交值。

## 6. 恢复与校验

启动 → 打开数据库／迁移 → 读取 profile → 校验存档 → 展示首页可用操作。不要在读取完成前提前创建新对局。

校验内容：

- schemaVersion 与 rulesVersion 可支持；未来版本不强行解析。
- 棋盘行列、每格类型、方块方向和整数坐标合法。
- 活动方块位置通过同一碰撞函数校验，分数为非负安全整数。
- 袋中类型有效且不重复，随机状态与算法版本合法。
- 时间在各自允许范围，锁定重置次数为 0–8，触底状态与锁定计时一致。
- sessionId、pieceId、revision、序号字段存在且类型正确。

校验成功后构造暂停快照，清空手势及副作用事件，重设时钟基线；继续后沿用剩余时间、袋和随机状态。若用户退出时已消行，恢复的是消行后的完整棋盘，不重播消行。

坏存档隔离或清除 active_session，不覆盖可读取的 profile；提示无法恢复并允许新游戏。数据库整体打不开时提示重试；可让用户明确选择仅临时游玩，但不能承诺保存最高分或进度。版本迁移在事务中完成，失败保留原数据，不自动清库。

## 7. 性能与平台行为

- 静态网格一次布局；已锁定格子在棋盘变化时更新，活动块和落点按位置变化更新。不要每帧重建 200 个格子的样式对象。
- 下落是逐格状态变化，稳定帧无状态变化时不触发整页渲染；动画只影响显示层。
- 快速拖动按采样累计位移生成必要步数，不为每个像素更新 React 状态。
- 音效随包提供，进入游戏时预备，后台停止；设备无震动或反馈调用失败时继续正常游戏。
- Android 返回：running → 暂停；暂停弹层返回不自动继续；设置返回关闭设置；结算返回首页；首页按系统默认退出。
- 竖屏和深色视觉通过 Expo 配置及组件主题统一；不存在原生目录时不手写 ios/ 或 android/。
- Android 安装包通过 EAS 构建，个人安装需选可直接安装的 Android 包配置；开发构建和最终离线构建均需测试，不能仅以 Expo Go 的结果验收。

存档测试必须人为延迟旧写入，并在其间结束／新开对局，验证不会复活旧存档；在事务提交前后模拟中断，验证不会出现棋盘和分数不匹配。性能测试记录设备、构建模式、输入反馈和帧表现，不把“目标 60fps”写成已验证结论。

实施时先统一项目使用的包管理器和锁文件；通过 `expo install` 安装 SDK 兼容依赖，不在文档阶段改动已有锁文件。每个开发阶段运行 lint 与 typecheck，并完成对应规则测试。本次文档检查若受现有依赖或 lint 配置阻塞，应如实记录，不为文档交付自动修复应用环境。
